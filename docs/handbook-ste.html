What are we achieving? Why do we need this?

The result is a gap you can measure again.

One agent answers one list of eight tasks. The agent does this three times. The model stays the same. The tasks stay the same. Only the context changes.

The scoreboard records three numbers for each run. The numbers are tasks passed, tool calls, and cost. The gap between the runs is the value of the context.

One agent Eight tasks Three contexts One model Seed 77

The requirements state the claim in one line. The context supplies the skill. The model stays fixed.

The gap is the defense of that claim.

An agent on a new repository fails in a known way. The agent searches by trial. The agent misses rules that live outside the code.

A person can add a map and a rule book by hand. Hand context has no measured effect. This harness measures the effect.

Why would someone pay me to solve this?

A customer pays for a first week that ends in numbers.

A company pays an engineer to make an agent useful on a system the agent has not seen.

In week 1 you learn the shape of the code. You also learn the rules of the trade. You then put that knowledge into the agent by hand.

This system turns those two jobs into files. The map holds the shape of the code. The corpus holds the rules. The harness writes the tasks from the map.

The customer can see the change in tasks passed, tool calls, and cost. A second person can run the same command. The fee is for that repeatable start, and for answers that cite a rule.

Job 1

Learn the code

The map is a graph of the repository. A node is a symbol. An edge says which symbol calls which symbol, and in which file.

Job 2

Learn the rules

The corpus is a folder of public industry documents. For the demo, the folder is banking law. The folder can be aviation text instead.

Job 3

Show the effect

A sponsor can read the scoreboard. A higher score and a lower cost are the business case in one view.

How do the three runs work, and why three?

Same work. Three levels of help.

Select an arm. The card lists the text the agent receives. The other conditions stay fixed, so the gap has one cause.

The gap from run 1 to run 2 is the value of the map. The gap from run 2 to run 3 is the value of the rules.

This arm is the baseline. The agent must search the repository with no map. A weak score here is the start of the gap.

This arm adds code knowledge. The diagram has a cap of 24 nodes. The agent sees one module, because a picture of the whole repository does not fit.

This arm adds domain knowledge. Before the arm starts, the bridge searches again. The log then shows the retrieval for this arm.

Caution — read the dollars this way

The seed cost is about two cents. Fake tasks report 100 prompt tokens and 20 completion tokens. The default rates are $0.15 and $0.60 per million tokens, plus $0.001 per tool call.

Those cents are a unit for comparison. On a real engagement the token counts are larger. Compare arms with the same formula. Quote a customer only from a real run.

What is already measured

Two real runs of qwen3:8b are on disk. The later one is scratch/live-reports. Code tasks: 0 of 4, then 4 of 4, then 4 of 4. Rule tasks: 0 of 4 in every sitting. Tool calls: 22, then 1, then 0. Cost: $0.03605, then $0.00343, then $0.00497.

The earlier run, scratch/actual-reports, has the same shape. Code tasks 0 then 4 then 4. Rule tasks 0. Tool calls 40, then 0, then 0. Cost $0.05138, then $0.00321, then $0.00560.

The seed above is still a fake-model rehearsal. Read the real numbers in the walk-in briefing. The Fineract map gate is separate: 21.697 seconds, 61,983 nodes, 303,539 edges.

Why is this better than work with no map and no rule book?

The agent stops the blind search, and the rule has a citation.

Question only

The agent searches by trial

The agent lists directories and reads files until it finds a symbol. Each extra tool call has a price. A rule lives outside the repository. The files alone do not show that rule.

You have one score. The score has no separate cause.

Map and rules

The agent goes direct

The prompt names the symbol and the file. The prompt can also include the rule text. A rule answer must cite a chunk id from the bridge.

Run 1 to run 2 isolates the map. Run 2 to run 3 isolates the corpus.

Bank rules do not live in the source files. The code can show that LoanProductHandler calls LoanProduct. The corpus holds the limit on a fee. An agent that reads only the code can miss that limit.

The jail and the cap matter here. The agent has two tools, list_dir and read_file. A path outside the repository raises PermissionError. Tool call 13 ends the attempt with an empty answer. An empty answer counts as a failed task. A lost agent stays visible. The run stays bounded.

Why not just write a basic eval?

A hand-written eval tests a pipeline. This harness tests the context.

This repo already has a basic eval. The command is python -m app eval. It runs ten fixed cases. It tests retrieval and generation. Keep it. It answers a different question.

The harness command is python -m app score. The subject is the agent. The generator builds the tasks from the map. The same graph yields the same four edges.

A hand-written list has three weak points. You choose the questions, so a critic can call them easy. The key can drift away from the code. One score hides the cause.

Here, a fixed sort selects extracted call edges and import edges. Loan paths come first. The sort takes four edges. Fewer than four edges and the run refuses to start.

The model writes only the words of the task. The instruction says: phrase a task list. Do not invent facts. If the model invents a tier-1 target, the harness keeps the graph target. If the model cites a chunk id that the bridge did not return, the run stops.

That is the reason for the extra machine. The exam carries its own key. The key was in the map and in the bridge log before the model spoke.

How does one score run work?

Eight steps. One command.

python -m app score --repo PATH --graph PATH --output PATH

01

Pick four edges

Load the graph. Keep extracted calls and imports. Sort loan paths first. Take four.

02

Search the corpus

The source label is the query. Example label: LoanProductHandler. The bridge returns chunks with ids and text. Each id goes to the log.

03

Phrase the tasks

One model call writes the words for eight tasks. Four tasks are code facts. Four tasks are rule questions. The model cannot supply the key.

04

Save the paper

The eight tasks become eight cases. The file tasks.json is the audit copy.

05

Run three arms

The same cases run three times. The prompt changes. One run id covers all three arms.

06

Let the agent answer

The agent may list and read files inside the repository. The cap is 12 tool calls. Temperature is 0. The seed is 77.

07

Grade on two tracks

Tier 1: the answer must contain the symbol and the file name. Tier 2: a judge must name one allowed chunk id. A second check confirms that id.

08

Write the board

One row per arm. Reports go to disk. Rows go to Postgres. Grafana reads those tables.

Direction rule

The map aims. The corpus fills.

Graph labels are the queries. Keep that direction. The corpus does not choose edges. Source code does not enter the vector store.

The map is exact, so the map can be a key. The corpus is prose, so the corpus can ground a rule. A mix of the two has no clean key.

The wrong way

Do not send source code into the corpus search.

Do not let the corpus pick the edges.

Do not take the tier-1 answer from the model text.

The cast

Two inputs feed one spine. The map is inside the repository. The corpus is outside it. The subject is the agent.

03 · Handbook §3Proof

Why Fineract

The generator accepts any graph with four good edges. A toy graph can pass the code. A toy graph cannot support the claim.

Apache Fineract is a real banking core, and it pairs with a public lending rule book. The gate measured 21.697 seconds, 61,983 nodes, and 303,539 edges. You can swap the repository with --repo.

At that size, the human diagram shows one module. The largest module offered 9,255 nodes. The cap is 24. That is why run 2 does not show a whole-repository picture.

04 · Handbook §4Core

The join

This is the trick. The graph has no questions. The corpus has no questions. The task is born at the join, and it is born with a key.

A fixed sort chooses the facts. A critic can read the sort. Swap the corpus folder and the rule questions change. The code stays the same.

05 · Handbook §5Guide

The analogy

Blueprint, code book, inspector, apprentice, master. Each role is one module.

The story is a memory tool. The story and the code name the same roles. When a debate starts, put the debate in the story first. Then return to the code.

06 · Handbook §6Core

Anatomy of one run

Eight steps from the command to the board. The worked edge is LoanProductHandler calls LoanProduct.

Read this section when you want the path of one task. The other sections comment on these steps.

07 · Handbook §7Proof

Pydantic Evals

The library holds the exam. A case is one task. A dataset is the eight tasks. An evaluator grades one case. A report evaluator sums the scoreboard.

Tests replace the model, the bridge, the judge, and the agent with fakes. CI checks the exam logic with no Ollama. The real model is configuration.

08 · Handbook §8Guard

The judge

A model writes the words. A model can grade the rule answer. That loop is a real risk.

Tier 1 is the grade you can check with no model. The grader is a script. The key is the graph edge. Tier 2 stays in its own column. The judge must name an allowed chunk id. A second check confirms the id. Tone alone cannot pass a task.

09 · Handbook §9Guard

OSSIE

OSSIE is a YAML contract for the datasets. An early file named graph tables that were not tables. Nothing read the file, so the error stayed hidden.

ossie materialize writes the graph into real Postgres tables. ossie validate checks every declared table and column. A miss exits with code 1 and names the miss. The contract and the database must agree.

10 · Handbook §10Core

Pins and cost

Temperature 0 and seed 77 are set on the agent and on the graders. Edge choice is a sort. Retrieval rank uses a fixed formula. A second run should build the same exam.

Cost is the column a budget owner can read. A lost agent explores at a high cost. A mapped agent goes to the target. The judge tokens count too. Grading is not free in the books. Set the rates to a real price before you quote a customer.

11 · Handbook §11Proof

The board

The sink writes four tables: runs, task results, tool calls, and gate metrics. Grafana shows five panel families and refreshes every 5 seconds.

The opening picture is the seed. Treat it as a rehearsal of the shape. Measured model numbers come from a real score run, which is a separate path in the demo rig notes.

12 · Handbook §12Guide

Glossary

The handbook lists pairs that people mix. Score and eval. Map and corpus. Tier 1 and tier 2. Graph and diagram. Run and arm. Sink and board.

Use it when a sentence in the handbook uses two names for one worry. Often the names are two objects.

Is it viable in production and in an enterprise?

The method can earn a fee. The rig is a measured demo.

An enterprise can use the method on an engagement now. Map the repository. Load a public rule folder. Run the three arms. Show the gap.

The rig is one machine. Ollama runs on the host. Docker runs Postgres and Grafana. The build uses public documents only. Access control for a private rule book is out of this build.

Sell the method as the first week of an engagement. Do not sell the rig as a finished platform for many customers.

Which words are fixed?

One word for each thing.

Agent
The program that reads the repository and answers the tasks. The program under test.
Map
Knowledge of the repository. A graph for the agent. A module diagram for a person.
Corpus
The folder of industry rules, loaded into Postgres.
Bridge
The search command. A text query in. Chunk JSON out. Every chunk id goes to the log.
Task
One exam question. Eight tasks make the list.
Tier 1
A code-fact task. The key is the graph edge. A script grades it.
Tier 2
A rule task. The key is the chunk ids. A judge and a citation check grade it.
Arm
One context level. The names are bare, map, and map_rules.
Run
All three arms under one run id.
Scoreboard
Tasks passed, tool calls, and cost for each arm.
Jail
The path check. It rejects files outside the repository.
Sink
The writer that fills the Postgres metric tables.
Board
The Grafana view that reads the sink.
Golden exam
The older ten-case test of the search pipeline. Command: python -m app eval.
OSSIE
The YAML contract. Validate checks it against the live database.
Gate
The scale run that mapped Fineract and stored the counts.
